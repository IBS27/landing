# Muse unit reconstruction experiment

The public [Great Heathmead listing](https://www.holroydhomes.co.uk/property/great-heathmead-haywards-heath-rh16/143312-000227/1) supplies a floor-plan image, interior/exterior photos and a [134-second walkthrough](https://www.youtube.com/watch?v=UHonGRH6n1o). The video title is “Pinfold House”; sampled rooms and finishes correspond to the linked listing. It was marked let agreed when inspected on 2026-11-13 UTC.

The default preview uses the reviewed floor-plan layout and **19 observed assemblies / 129 parts** generated by Muse Wonder from the photos and full video. It includes fitted kitchen units, appliances, bathroom fixtures, radiators, curtains and lighting. Geometry and fixture coordinates were not edited by hand; model revisions received validation errors and visual-review feedback.

The initial mixed-media passes misplaced openings despite a readable plan. The application now gives explicit floor-plan media priority for topology; photos/video are read in the appearance pass. Without a floor plan, layout inference falls back to the available photos/video. This reduces conflicting perspective cues but does not establish accuracy without review.

## Fidelity assessment

The main room arrangement follows the plan: lounge on the left, two bedrooms across the top, kitchen below the lounge, an L-shaped hall, bathroom and small compartments. The stepped bedroom boundary is preserved. The final scene has the broad lounge sliding door on the north wall, a separate west window, and a solid south kitchen wall. The original model had mistaken the sink/drainer symbol for a window. Muse refitted the kitchen, curtains and radiators after correcting those openings.

The final output passes schema, bounds, source-reference and doorway-clearance checks. A 10 cm navigation grid with an 18 cm walker radius reaches all eight room centers from the hall, including fixture collisions. This checks traversability, not similarity to reality.

Remaining limits:

- The plan has no printed dimensions. Absolute size, ceiling height and furniture fit remain unverified; a measured reference is needed.
- The small kitchen cupboards/lobby are simplified. The unlabeled bathroom-side compartment and its access remain uncertain.
- Materials use photo-derived colors and procedural grain, carpet and tile detail. The patterned bathroom floor is averaged into a generic tile finish. Trim profiles and hidden surfaces are approximations.
- Fixtures are parametric assemblies, not scanned meshes. The viewer adds bevels, reflections, shadows, contact shading and cutaway walls, but this is not a photorealistic digital twin.

[Rumi](https://github.com/IBS27/rumi) was the implementation reference, particularly its distinction between an editable simulated room and captured surfaces. Its captured-surface pipeline has measured meshes and calibrated camera poses. This experiment has neither and does not claim equivalent scan fidelity.

## Reproduce

Provide `MODEL_API_KEY` in the process environment. Never commit it. Source media binaries are not committed.

```sh
bun scripts/unit-scenes/reconstruct.ts scripts/unit-scenes/heathmead.sources.json /tmp/unit-layout.json
```

The current script follows the production policy: a labeled floor plan controls geometry when available. The earlier photo/video baselines record the prior mixed-media policy. To reproduce the layout review with its original feedback and reference:

```sh
bun scripts/unit-scenes/reconstruct.ts scripts/unit-scenes/heathmead-plan.sources.json /tmp/unit-reviewed.json scripts/unit-scenes/heathmead-video.result.json
```

For appearance, copy `heathmead.sources.json` to a temporary manifest and append a source with `key: "video-tour"`, `kind: "video"`, a descriptive `label`, and `localFile` pointing to the downloaded MP4 tour. The script sends inline video bytes.

```sh
bun scripts/unit-scenes/appearance.ts /tmp/with-video.sources.json /tmp/unit-reviewed.json /tmp/unit-detailed.json
```

An input layout may include a prior appearance; the script sends it with current validation failures for correction. The manifest can also contain a `corrections` string array with visual-review findings. Outputs vary between runs.

The offline action context supplies the agent's source/cache/log calls locally. Actual inference uses Meta's API through the production adapter. No Convex deployment writes occur. Output records include the model, attempts, usage, elapsed time and validation result.

## Preview and verification

Open `/scripts/unit-scenes/preview.html` on this checkout's Vite server. It uses the production editor and switches between the photo baseline, video baseline, and final detailed reconstruction. Edits on this page stay in browser storage. The app route `/landing/place/unit` uses private Convex records and requires the owner to deploy the new backend through the normal main-branch workflow.

```sh
CHROMIUM_PATH=/path/to/chrome bun scripts/unit-scenes/verify-browser.ts http://host:port/scripts/unit-scenes/preview.html
```

This exercises rendering, cutaway/details toggles, view modes, keyboard turning, furniture edits, overlap warnings, scale calibration, save/reload, shared-corner editing and mobile overflow. Screenshots go to `/tmp/landing-unit-evidence/`. Registered-handler tests cover persistence and authorization; the shared backend has not been deployed or browser-verified from this worktree.
